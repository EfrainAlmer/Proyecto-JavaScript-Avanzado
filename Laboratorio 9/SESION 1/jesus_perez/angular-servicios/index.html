1. Servicios (Services)

Un servicio es una clase con código o datos que varios componentes necesitan.

Piensa en: la cocina. Los meseros (componentes) no cocinan: le piden los platos a la cocina. Así no repiten el trabajo.

Pruébalo

Toma pedidos con los dos meseros y cambia la opción para ver la diferencia.


Mesero A
    Mesero B

      Así se escribe

      // pedidos.service.ts  (la cocina)
@Injectable({ providedIn: 'root' })   // Angular crea UNA sola
export class PedidosService {
  pedidos = signal<string[]>([]);
  agregar(plato: string) {
    this.pedidos.update(lista => [...lista, plato]);
  }
}

// en un componente (el mesero): se pide con inject(), no con new
export class MenuComponent {
  cocina = inject(PedidosService);
}

      2. HttpClient

      HttpClient es la herramienta de Angular para comunicarse con un servidor.

      Piensa en: el repartidor. Va al almacén, trae los productos y los entrega. A veces tarda, y a veces el almacén está cerrado (error).

      Pruébalo

      Esta demo simula un servidor dentro de tu navegador. Pulsa una acción y lee qué pasó.

      Pulsa una acción.

      Así se escribe

      // 1) Activar HttpClient una vez, en app.config.ts
providers: [ provideHttpClient() ]

// 2) Usarlo dentro de un servicio
@Injectable({ providedIn: 'root' })
export class PlatosService {
  private http = inject(HttpClient);
  private url = 'http://localhost:3000/platos';

  listar()            { return this.http.get<Plato[]>(this.url); }
  crear(plato: Plato) { return this.http.post<Plato>(this.url, plato); }
  borrar(id: number)  { return this.http.delete(`${this.url}/${id}`); }
}

// 3) En el componente: subscribe espera la respuesta
this.servicio.listar().subscribe({
  next:  (platos) => this.platos.set(platos),       // salió bien
  error: ()       => this.mensaje.set('Falló la carga') // salió mal
});

      3. JSON Server

      JSON Server convierte un archivo db.json en una API falsa que funciona de verdad.

      Piensa en: un almacén de juguete para practicar con el repartidor, sin construir un servidor real.

      Paso 1: crea el archivo db.json

      {
  "platos": [
    { "id": 1, "nombre": "Pizza",   "categoria": "comida", "precio": 28 },
    { "id": 2, "nombre": "Ceviche", "categoria": "comida", "precio": 35 },
    { "id": 3, "nombre": "Limonada","categoria": "bebida", "precio": 8 }
  ]
}

      Paso 2: enciende el servidor

      npx json-server db.json
# Queda en http://localhost:3000
# (en versiones antiguas: json-server --watch db.json)

      4. Herramientas para probar los servicios
      
  
      Probar un servicio es comprobar que funciona sin usar el servidor real.
      
  
      Piensa en: el inspector. Le da un pedido falso a la cocina y revisa que el resultado sea el correcto.
      
  
      Pruébalo
      
  
      Ejecuta las pruebas. Luego activa "romper el servicio" y vuelve a ejecutarlas: verás cómo una prueba detecta el error.
      
  
      
    
      
    
      
    
      
  
      
  
      Así se escribe una prueba
      
  
      beforeEach(() => {
  TestBed.configureTestingModule({
    // servidor falso para las pruebas
    providers: [provideHttpClient(), provideHttpClientTesting()],
  });
  servicio = TestBed.inject(PlatosService);
  http = TestBed.inject(HttpTestingController);
});

it('listar() hace un GET a /platos', () => {
  servicio.listar().subscribe(r => expect(r).toHaveLength(2));

  const req = http.expectOne('http://localhost:3000/platos'); // atrapa la petición
  expect(req.request.method).toBe('GET');
  req.flush([{ id: 1 }, { id: 2 }]);  // responde con datos falsos
});

afterEach(() => http.verify());  // no deben quedar peticiones sin responder

      Mini glosario
      
  
      
    
      Servicio
      Clase con lógica o datos compartidos entre componentes.
      
    
      Inyección de dependencias
      Angular te entrega lo que pides con inject(); tú no lo construyes.
      
    
      API REST
      Direcciones de un servidor que se usan con GET, POST, PUT, PATCH y DELETE.
      
    
      Observable y subscribe
      Una respuesta que llega más tarde; subscribe espera a que llegue.
      
    
      JSON
      Formato de texto para datos, por ejemplo {"nombre": "Pizza"}.
      
    
      Simulación (mock)
      Respuesta falsa que se usa para probar sin servidor real.
      
  
      

      

      

      Las demostraciones son simuladas en tu navegador: no hay un servidor real detrás.
